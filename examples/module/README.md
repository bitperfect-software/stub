# module

A tiny in-memory record store, generated from an entity name. Four templates that between them use
every feature `stub` has in 0.1.0.

## What it shows

| Feature | Where |
|---|---|
| a **variable** | `entity` — the positional argument |
| a global **computed** | `entityPlural`, and `dir` built from it |
| a template-local **computed** that shadows a global | `modelTest` redeclares `dir`, so its file lands under `tests/` while its siblings land under `src/` |
| a **switch** | `--noDelete` drops the remove function from the store |
| transitive **requires** | `model` pulls in `store` and `modelTest` |
| `{% path %}` **inside a `{% render %}` partial** | `header.liquid` is included by `model` and `store` and still resolves the model's target |
| `{% reference %}` with **named formats** | `default` for the `@/` alias, `relative` for a same-directory import |
| **filters** | `plural`, `kebabCase`, `pascalCase`, `camelCase`, `noCase` |

`header.liquid` has no entry under `templates`: it is a partial, included with `{% render %}`, not a
file `stub` writes.

## Running it

```bash
cd examples/module
stub model Invoice
```

Writes three files:

```
src/invoices/Invoice.ts
src/invoices/invoiceStore.ts
tests/invoices/Invoice.test.ts
```

`src/invoices/Invoice.ts`:

```ts
// Generated by stub. Model: src/invoices/Invoice.ts
// Regenerate it rather than editing it — the source of truth is .stub/.

export interface Invoice {
    id: string;
    label: string;
    createdAt: string;
}

/** New invoice fields — the store adds id and createdAt. */
export type NewInvoice = Omit<Invoice, "id" | "createdAt">;
```

`src/invoices/invoiceStore.ts`:

```ts
// Generated by stub. Model: src/invoices/Invoice.ts
// Regenerate it rather than editing it — the source of truth is .stub/.

import type { Invoice, NewInvoice } from "./Invoice";

const invoices = new Map<string, Invoice>();

export const addInvoice = (draft: NewInvoice): Invoice => {
    const invoice = { ...draft, id: String(invoices.size + 1), createdAt: new Date().toISOString() };

    invoices.set(invoice.id, invoice);
    return invoice;
};

export const listInvoices = (): Array<Invoice> => [...invoices.values()];

export const removeInvoice = (id: string): boolean => invoices.delete(id);
```

`tests/invoices/Invoice.test.ts`:

```ts
import assert from "node:assert/strict";
import { test } from "node:test";
import type { NewInvoice } from "@/invoices/Invoice";
import { addInvoice, listInvoices } from "@/invoices/invoiceStore";

test("stores a new invoice", () => {
    const draft: NewInvoice = { label: "first" };

    addInvoice(draft);

    assert.equal(listInvoices().length, 1);
});
```

## The two reference formats

`store.liquid` and `modelTest.liquid` both import the model, but they sit in different trees, so they
ask for different formats of the same target:

```liquid
{% reference 'model' as: 'relative' %}   ./Invoice              in src/invoices/invoiceStore.ts
{% reference 'model' %}                  @/invoices/Invoice     in tests/invoices/Invoice.test.ts
```

The bare call works because one of the declared formats is literally named `default`.

## The switch and the override

```bash
stub model Invoice --noDelete --entityPlural Invoicen
```

`--noDelete` removes `removeInvoice` from the store — a switch removes **content inside a file**, never
a file. `--entityPlural Invoicen` replaces the derived plural everywhere it is used, including inside
`dir`, so the same run writes:

```
src/invoicen/Invoice.ts
src/invoicen/invoiceStore.ts
tests/invoicen/Invoice.test.ts
```

That is the point of `computed`: one override reaches every template in the chain, because each of them
derives its own values from the same raw input.

## Rendering one template on its own

```bash
stub --noRequires model Invoice
```

Writes `src/invoices/Invoice.ts` and nothing else. `--noRequires` is a program option, so it goes
**before** the command name. The `{% path %}` in the banner still resolves, because targets are
resolved for the whole manifest, not just for what this run writes.
